Current Challenges
03 / 09

当前测试准备流程的主要问题

现阶段的核心问题不是测试做不做，而是测试准备环节仍然高度依赖人工整理、人工判断和人工同步。

Pain Point 01

需求信息获取效率低

测试人员需要在 JIRA、需求文档、会议纪要之间来回切换，才能整理出真正可执行的测试输入。

Pain Point 02

用例质量受个人经验影响

不同人员生成的测试用例深度不同，主流程容易覆盖，但边界与异常场景往往不够系统。

Pain Point 03

结果回填存在重复劳动

生成完成后还需要复制、整理、同步到 JIRA，闭环不顺畅，过程也不够透明。

使用体验关注点 当需求量持续上升时，如果准备流程仍靠人工扩张，使用者会明显感受到效率下降、操作繁琐和结果不稳定。
核心信息：把重复劳动自动化，把经验能力结构化。
Closed Loop
04 / 09

从需求到测试资产的完整闭环

工具的价值不是“生成一份文案”，而是把整个测试准备过程变成一条标准、可复用的自动化链路。

1

输入

支持输入 JIRA 工单编号，或上传本地需求文件。

2

提取

精准提取 description 等需求字段，支持多数据源切换。

3

生成

自动产出标准化测试用例，覆盖主流程、边界和异常场景。

4

确认

支持人工快速审阅和调整，兼顾效率与准确性。

5

回填

一键同步回 JIRA，实现需求与测试用例的一体化管理。

What Changes

流程由离散动作变成标准链路

  • 减少信息切换、手工整理和重复录入。
  • 让需求工单直接成为测试资产的入口。
  • 为跨项目推广打下统一流程基础。
Applicable Scenarios

适用于高频需求和快节奏交付

  • 需求量大、交付节奏快的研发团队。
  • 需要较强追踪性和过程透明度的项目。
  • 同时存在线上工单和线下文档需求的场景。
重点表达：这不是点状功能，而是贯穿需求到测试的流程升级。
Core Functions

核心功能结构

主功能负责打通业务主链路，辅助功能负责保障接入、权限与追踪能力。

  • 按需提取 description 等关键字段。
  • 支持 WBP 等多数据源适配。
Core Capability

需求驱动的测试用例智能生成

  • 输出标准化表格结果，降低从零编写成本。
  • 包含 ID、描述、前置条件、步骤、预期结果。
  • 自动覆盖主流程、边界和异常场景。
Core Capability

测试用例一键同步 JIRA

  • 用例生成后直接回填目标工单。
  • 减少复制粘贴和人工整理工作。
  • 形成需求到测试资产的完整闭环。
Core Capability

双模式输入适配

  • 既支持 JIRA，也支持本地需求文件。
  • 适配无工单的线下需求场景。
  • 提升工具适用范围和灵活性。

系统权限对接配置

  • 支持 GRA / Confluence token 配置。
  • 保障检索、拉取和同步操作可用。
  • 降低不同环境的接入门槛。
Supporting Feature

历史记录查询

  • 支持按 source 类型筛选历史记录。
  • 便于复用、回查和问题定位。

Output Example
06 / 09

生成结果示意

输出结果是标准化、可同步、可追踪的测试资产，而不是单次使用的自由文本。

Test Case Id Test Case Description Preconditions Test Steps Expected Results
TC-001 Generate test cases from a valid JIRA ticket User has a valid token and enters an existing JIRA ticket number. 1. Input ticket number. 2. Select source. 3. Click generate. System retrieves requirement details and generates structured test cases successfully.
TC-002 Handle missing description in requirement data The selected JIRA ticket exists but description is empty. 1. Input ticket number. 2. Click generate. 3. Observe prompt. System shows a clear message indicating missing requirement content and asks the user to supplement or correct the input.
TC-003 Handle invalid token during retrieval User token is expired or invalid. 1. Input valid ticket number. 2. Click generate or sync. 3. Observe system response. System returns a clear authorization error and blocks further retrieval or sync actions.
TC-004 Sync generated test cases back to JIRA Structured test cases have already been generated successfully. 1. Review generated cases. 2. Click sync to JIRA. 3. Check history record. System syncs test cases to the target JIRA ticket and records the operation history.
Why It Matters

结构化输出的意义

  • 便于测试执行、复审和后续复用。
  • 便于与 JIRA 形成一致的追踪关系。
  • 便于跨项目使用统一标准进行推广。
  • 便于把团队经验沉淀为可复制的方法。
演示建议 现场讲解时可以强调“输出可以直接进入团队流程”，这会比单纯展示 AI 文本更有说服力。
重点表达：标准化结果是组织资产，而不是一次性内容。
