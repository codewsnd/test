02 Business Pain Points
02 / 08

为什么我们需要这套工具

在传统测试流程中，需求信息分散、用例依赖人工经验、结果回填重复劳动，导致效率波动大、覆盖不稳定、质量追踪困难。

痛点 01

需求理解成本高

测试同学需要频繁在 JIRA、会议纪要、附件文档之间切换，手动定位需求关键字段，信息整理耗时长、容易遗漏。

痛点 02

用例输出不稳定

不同人员的经验差异会直接影响测试用例质量，主流程容易覆盖，但边界场景和异常场景往往不够系统。

痛点 03

闭环追踪效率低

用例生成后还需要人工复制、整理、回填 JIRA，重复操作多，需求与测试资产之间的关联维护成本高。

我们的切入点

  • 把“需求拉取、智能生成、同步回填”做成一条可复用、可审计、可放大的自动化主链路。
  • 把测试经验沉淀成标准化结构输出，让团队能力从个人经验转变为平台能力。
  • 把历史记录、权限配置、多数据源适配纳入同一工具域，形成可持续扩展基础。
核心诉求：降低人工整理成本，提升测试覆盖质量，强化需求与测试联动。
03 Closed-Loop Workflow
03 / 08

一条完整的自动化闭环

工具不是单点生成器，而是从需求源头到测试资产沉淀的闭环平台。

1

输入需求

支持 JIRA 工单编号输入，也支持上传本地需求文件。

2

精准提取

按字段抓取 description 等关键内容，并支持多数据源切换。

3

智能生成

自动产出标准化测试用例，覆盖主流程、边界和异常场景。

4

人工确认

支持测试人员快速预览、校准与二次编辑，提高可控性。

5

同步回填

一键上传至 JIRA，实现需求与测试用例的一体化管理。

闭环优势

  • 把离散操作串成标准流程，减少人为切换和遗漏。
  • 让需求工单成为真实的测试资产入口，而不是单纯记录工具。
  • 支持项目级复制推广，不依赖单个人员的测试经验沉淀。

适用场景

  • 研发节奏快、需求量大、JIRA 工单规范程度较高的团队。
  • 存在大量回归测试与多版本交付，要求用例资产可追溯的项目。
  • 需要同时覆盖线上 JIRA 需求与线下临时文档需求的业务场景。
重点不是“生成一次”，而是把测试资产持续沉淀回业务流程。
04 Core Functions
04 / 08

核心功能矩阵

工具围绕主功能链路与辅助能力搭建，既解决眼前效率问题，也具备持续演进的扩展空间。

核心主功能

JIRA 工单精准检索与信息提取

  • 支持输入工单编号快速定位目标需求，如 PHH-616。
  • 可按需提取 description 等指定字段，拿到测试生成所需核心信息。
  • 支持多数据源切换，适配不同项目、环境和组织域。
核心主功能

需求驱动的测试用例智能生成

  • 自动生成标准化表格化用例，减少从零编写的人力投入。
  • 内置用例字段：用例 ID、描述、前置条件、操作步骤、预期结果。
  • 覆盖主流程、边界场景、异常操作等关键测试点。
核心主功能

测试用例一键同步 JIRA

  • 支持生成完成后回填至对应 JIRA 工单，形成闭环。
  • 减少复制粘贴与手工整理，降低重复操作成本。
  • 加强需求与测试资产的一体化管理能力。
核心主功能

双模式输入适配

  • 支持 JIRA 工单输入，也支持本地需求文件上传。
  • 兼容无工单的线下需求、临时评审稿与补充文档场景。
  • 提升工具适用范围，避免流程被系统边界限制。
辅助配套

权限与系统对接配置

  • 支持配置 GRA / Confluence token，保障检索与同步链路畅通。
  • 统一权限入口，减少环境差异造成的接入阻塞。
  • 便于推广到更多项目团队与业务域。
辅助配套

历史记录查询与可追踪

  • 支持按 source 类型筛选查看操作历史。
  • 方便复用过去的结果，支撑日常回查与问题定位。
  • 当前限制：暂不支持直接全量检索，后续将继续优化。
主链路解决效率问题，辅助能力保证工具可接入、可追踪、可推广。
05 Demonstration Output
05 / 08

生成结果长什么样

工具输出的是可直接用于测试执行与沉淀的标准化结果，而不是一段无法复用的自由文本。

测试用例输出示例

用例 ID 用例描述 关键内容
TC-001 通过 JIRA 工单生成标准测试用例 校验输入工单号后，系统能正确拉取需求并输出完整用例表。
TC-002 边界场景覆盖 当 description 字段为空或字段缺失时，系统需提示并支持补充输入。
TC-003 异常场景处理 当 token 失效、数据源不可用时，系统需给出明确错误反馈。
TC-004 回填同步验证 生成后的测试用例可以一键同步到目标 JIRA 工单并记录操作历史。

输出结构价值

标准化

统一字段结构，便于测试执行、复审、沉淀与后续复用。

可审阅

测试人员可在同步前快速确认，保障 AI 输出的可控性和业务准确性。

可追踪

结果回填 JIRA 后，需求与用例形成强关联，方便回溯与对齐。

可复制

面向不同团队与业务线时，依然可以沿用相同的结构标准。

07 Roadmap
07 / 08

下一步优化方向

当前主链路已经完整，接下来重点从“搜索体验、平台能力、规模化应用”三个维度继续增强。

短期优化

体验完善

  • 优化历史记录搜索，支持更灵活的全量检索与筛选组合。
  • 提升异常提示的可理解性，让权限、接口、字段问题更容易定位。
  • 增强生成结果的可编辑体验，缩短人工确认时间。
中期建设

平台能力强化

  • 沉淀场景模板，让不同业务线可复用行业化测试策略。
  • 引入生成质量评估机制，持续优化用例覆盖效果。
  • 扩展更多外部系统与数据源连接能力。
长期价值

从工具到平台

  • 形成组织级测试资产中心，统一管理需求、用例和执行结果。
  • 将 AI 生成能力延伸到回归测试编排、缺陷分析和质量洞察。
  • 支持跨团队、跨项目的质量治理与效能度量。
已知待优化项

当前说明

历史记录搜索当前需要先选择 source 类型，暂不支持直接全量检索。该问题已明确纳入后续优化范围，不影响核心闭环能力使用。
